# URL Shortener

Учебный проект для сокращение ссылок с REST API, написанный на Go.

## Features

- сокращение ссылок
- редирект по короткому коду
- health-эндпоинт

Реализована слоистая архитектура, тесты, конкурентная безопасность и
запуск в Docker. 

## Технологии
- Go
- PostgreSQL
- pgx
- Docker / docker compose

## Как запустить

Склонируйте репозиторий, создайте `.env` по образцу `.env.example`.
В файле `.env` находится DATABASE_URL с хостом db. Скопируйте и вставьте в 
свой файл `.env`:
```bash
DATABASE_URL=postgres://shortener:secret@db:5432/shortener
```
Значения должны совпадать с значениями для базы данных в указанные в 
файле docker-compose.yml(POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB). 

Выполните в корне проекта команду `docker compose up` . Создайте таблицу 
следующей командой: 
```bash
docker compose exec db psql -U shortener -d shortener -c "CREATE TABLE links(code VARCHAR(5) PRIMARY KEY, url TEXT NOT NULL);"
```

Обязательно проверьте создалась ли таблица следующей командой:
```bash
docker compose exec db psql -U shortener -d shortener -c "\dt"
```

Тесты можно запустить командой:
```bash
go test -race ./...
```

## API эндпоинты

Сервис слушает http://localhost:8080, запросами можно стучаться сюда.

- POST /shorten с телом где находится ссылка по которой надо дать код -> 
получаете структуру с полем "short_url" с уникальным кодом который сохранится 
в базе данных и можно будет по ней перейти.
- GET /{code} - редирект на оригинальную ссылку. Вы можете убедится в этом в 
поле Location находится оригинальная ссылка.
- GET /health - для проверки сервиса. Запущена ли она или нет.

## Архитектура

Слои были Handler -> Service -> Storage разделены в одном файле чтоб 
можно было менять каждый слой при надобности. Для Storage слоя объявлен 
интерфейс для удобства в тестах. В тестах было подсунуто мапа вместо 
реальной базы данных. Каждый слой зависит только от соседнего и не ипользует
функции слоя перепрыгнув через соседний слой, слои изолированы.
